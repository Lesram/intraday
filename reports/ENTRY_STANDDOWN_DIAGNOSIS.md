## 3. Does the live path fire on a trending/high-vol session?

**Session 1 answer: no — and starvation, not regime, is why.** 2026-07-23 was 74%
trending_down (momentum/breakout-eligible per REGIME_POLICY), the live path generated
17 candidates, and still **zero filled.** The `direction_zero` (25) and liquidity (7)
kills DID fire late in the session, but they are second-order — 32 events against 1,746
starvation events. The primary binding constraint is **IEX data starvation** (empty
screener + stale bars), not the chop/`direction_zero` mechanism the plan assumed. The
plan's hypothesis ("chop → `direction_zero` → no fills") is not the dominant story;
IEX starvation is.

**Four-session answer (final, 2026-07-29):** the live path **can** fire — 07-27
proved it end-to-end (candidate → entry submission → fill → stop-loss exit, forward
n=1) — but across four sessions the pattern is stark: **22 live candidates → 1 fill
(4.5%)**, starvation never below ~2,000 events/session (scanner empty 164–252×,
stale bars 1,582–2,292×, SH/PSQ always worst), and the single fill landed in a 96%-chop
session's minority window rather than on a genuine trend tape. Both stand-down
mechanisms are now characterized: chop tape → `direction_zero` does the killing
(124–183×/session on 07-24/27/28); any tape → IEX starvation suppresses the candidate
flow an order of magnitude harder. The evidence-accrual rate at this data quality is
~0.25 fills/session — at that pace the n=60 verdict corpus needs ~240 sessions
(~1 year). That number, not any code defect, is the case for the data-feed DECISION
ITEM below. Table complete; obligation closed.
